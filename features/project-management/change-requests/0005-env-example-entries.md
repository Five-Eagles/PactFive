# CR-0005 — 루트 `.env.example` 이 비어 있다

| | |
|---|---|
| 제기 | 유동우 (project-management) · 2026-09-01 |
| 대상 | 김락원 (팀장 · 저장소 루트) |
| 상태 | 제안 — 제 쪽 코드는 이미 `.env` 주입으로 바꿨다 |
| 근거 | 팀 공지 2026-09-01 "외부 API 키는 루트 `.env` 를 통해 주입받는 형식으로 재설계" |

## 요약

루트 `.env.example` 이 **0바이트 빈 파일**이다. 초기 커밋(2026-08-24) 이후 변경이 없다.

공지대로 각자 `.env` 주입으로 바꾸려 해도 **무엇을 넣어야 하는지 적을 곳이 없다.**
`.env` 는 저장소에 올라가지 않으므로, `.env.example` 이 유일한 목록이다.

## 왜 직접 고치지 않았나

루트 공유 파일이라 네 명이 동시에 손대면 충돌이 난다. 담당 영역 밖 변경은
요청으로 남기는 것이 팀 규칙이기도 하다.

## 제 도메인이 필요한 항목

```dotenv
# ── 서버 간 인증 ────────────────────────────────
# /internal/v1 계약 함수 호출에 붙는다. 사용자 로그인 토큰으로는 접근할 수 없다.
# (features/project-management/spec.md 규칙 49)
# 없으면 개발에서는 경고 후 기본값, 운영에서는 서버가 뜨지 않는다.
INTERNAL_SERVICE_TOKEN=
```

**한 줄뿐이다.** 이 도메인은 외부 벤더를 부르지 않는다.

`engagement` 도 필요한 키가 없다.

## 넣지 않은 것

개발용 로그인 토큰(`pactfive-mock-client-01` 등, 규칙 54)은 `.env` 로 옮기지 않았다.
비밀값이 아니라 **"이 값이면 이 사용자"라는 팀 약속**이고, 팀 전체가 같은 값을 써야
서로 붙여볼 수 있다. 실제 인증이 붙으면 통째로 사라질 표다.

`features/project-management/prototype/server/config.ts` 에 그대로 두었다.

## 제 쪽에서 이미 한 것

`config.ts` 를 만들어 코드에 박혀 있던 값을 걷어냈다.

| 없을 때 | 어떻게 |
|---|---|
| 개발 | 기본값으로 뜨되 **경고를 한 번 남긴다** |
| 운영 | **즉시 실패한다.** 서버가 뜨지 않는다 |

떠서 요청마다 `401` 을 뱉는 것보다 배포가 멈추는 쪽이 빨리 발견된다.
`run.tsx` 에 네 경우를 검사로 넣었다.

## 참고

"보충 예정"으로 알고 계신 것으로 이해하고 있어 여기서는 항목만 적어둔다.
