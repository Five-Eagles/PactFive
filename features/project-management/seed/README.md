# 시드 데이터 — project-management 담당분

| | |
|---|---|
| 담당 | 유동우 |
| 근거 | RFP §7.2 (**필수**) · PRD §9.3 시드 프로젝트 12건 |
| 상태 | **프로젝트 12건 완료.** 나머지 단계는 아래 표 참고 |

## 무엇인가

RFP §7.2 가 **"배포된 서비스에서 즉시 동작을 확인할 수 있어야 함"** 을 필수로 요구한다.
발표에서 배포 URL 로 전체 흐름을 시연해야 하는데, 데이터가 없으면 그 자리에서
회원가입부터 시작해야 하고 **"마감 임박"이나 "작업 중" 같은 상태는 즉석에서 만들 수 없다.**

이 폴더는 그중 **프로젝트 12건**을 채운다.

## 실행

```bash
node features/project-management/seed/seed-projects.mjs
```

| 옵션 | 기본값 | 언제 |
|---|---|---|
| `--base` | `http://localhost:3000` | 배포 서버에 넣을 때 |
| `--token` | mock 인증 고정 토큰 | 실제 인증이 붙은 뒤 |
| `--dry-run` | — | 무엇이 들어갈지만 볼 때 |

`SEED_BASE_URL` · `SEED_TOKEN` · `SEED_ORIGIN` 환경변수로도 받는다.
**토큰을 코드에 박지 않았다.**

### 확인된 결과 (2026-09-03, 로컬)

```text
만든 것 12건 · 실패 0건
  OPEN 7 · SCHEDULED 1 · CLOSED 4
기본 목록 8건 (규칙 10 대로 마감 4건 제외) · 마감만 조회 4건
```

## 순서가 곧 의존성이다

```text
① 계정 6개      오민혁 (user-management)     ← 먼저 돌아야 한다
② 프로젝트 12건  유동우 ← 이 폴더
③ 지원          팀장 (applications)
④ 계약·결제·리뷰  조준영 (contracts-payments · reviews)
```

**①이 없으면 ②가 못 돈다.** 지금은 mock 인증의 고정 토큰으로 도는데,
실제 인증이 붙으면 `client-a` 로 로그인한 토큰이 필요하다.

## 이 스크립트가 채우지 못하는 것

돌리면 마지막에 목록으로 찍어 준다. **조용히 빠뜨리지 않는다.**

| 시드 | 무엇이 더 필요한가 | 담당 |
|---|---|---|
| P02 · P03 · P08 · P09 · P10 · P11 | 지원 1~3건 | 팀장 (applications) |
| P09 | 거래 `CONTRACT_PENDING` | 조준영 |
| P10 | 거래 `IN_PROGRESS` | 조준영 |
| P11 | 거래 `COMPLETED` | 조준영 |

거래 상태는 **직접 써 넣으면 안 된다.** `startProjectTransaction` ·
`completeProjectTransaction` 같은 내부 계약을 거쳐야 상태 조합 규칙(PRD §2.5)이 지켜진다.

## 두 가지 판단

**1. 마감일을 절대 시각으로 박지 않는다.**

`projects.json` 은 `deadlineInDays`(실행 시점 기준 상대 일수)로 둔다.
박아 두면 며칠 뒤 시연할 때 전부 마감으로 보인다 (PRD §9 유의사항 2).

시각은 **그날의 끝(23:59:59)** 으로 잡는다. `지금 + 1일` 로 하면 P12 가
"최소 1일 뒤" 검증에 걸린다 — 딱 24시간은 경계값이다. 그리고 마감일은 원래
시각이 아니라 날짜다. "9월 4일 마감"이면 그날이 끝날 때까지 지원할 수 있어야 한다.

**2. CLOSED 를 직접 써 넣지 않는다.**

등록 API 는 지난 마감일을 받지 않으므로 CLOSED 인 것을 그대로 만들 수 없다.
**미래 마감으로 만든 뒤 `close-recruitment` 를 부른다** — 실제 전이를 거치면
저장값과 조회 시점 판정(규칙 14)이 어긋나지 않는다.

## `projects.json` 을 고칠 때

PRD §9.3 표에는 **제목·카테고리·모집 상태·지원 건수만** 있다.
설명·예산·요구 기술·의뢰인은 이 파일이 정본이다 — 없으면 시드를 만드는 사람이
project-management 데이터를 추측해서 지어내게 된다.

값을 바꾸면 `demo/data.js`(시안)와 어긋날 수 있다. 두 곳이 같은 12건을 쓴다.
