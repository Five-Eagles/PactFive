## ux-philosophy.md §6 자체 점검

`design/` 이 있는 기능이라 해당된다. 팀장 통합 게이트의 같은 검증을 **대신하지 않는다** —
그 앞에 두는 담당자 자체 점검이다.

**7항목 전부 충족.** 2026-09-02 점검에서 3건이 미충족이었고 **같은 날 셋 다 고쳤다** (CR-0006).

| 검증 항목 | 이 화면에서 어떻게 충족하는가 (또는 왜 못 하는가) |
|---|---|
| 상태 이해 | ✅ 모집 상태 배지 + 거래 상태 배지(의뢰인만)로 두 축을 각각 보여준다. 마감은 `2026.09.08 · D-6` 처럼 절대·상대를 함께 준다. `availableActions` 로 다음에 무엇을 할 수 있는지 서버가 알려주고, 막힌 버튼에는 `지원자 3명이 있어 삭제할 수 없습니다` 처럼 이유를 붙인다 |
| 근거 이해 | ✅ **2026-09-02 개선.** 규칙 8 이 AI 분석 금액으로 사용자 입력을 덮어쓰는데 그 사실이 어디에도 남지 않던 것을 발견했다. `budget_source`(`CLIENT_INPUT`/`AI_ANALYSIS`)와 기록 시각을 저장하고, `MoneyBreakdown` 으로 `AI 단가 분석이 제안한 금액입니다 · 2026.09.01` 처럼 출처를 문장으로 보여준다. AI 값이면 되돌릴 수 있다는 것까지 알린다. **출처를 모르면 아무 말도 하지 않는다** — 지어내지 않는다. 등록 의뢰인만 본다(공개 응답에는 키가 없다). ERD 컬럼은 CR-0007 로 요청했고 그 전까지는 Mock 에서만 유지된다. `run.tsx` 검사 12건 |
| 작업 보호 | ✅ **2026-09-02 개선.** 단계 사이 이동은 원래 유지됐고, 새로고침·뒤로 가기에 사라지던 것을 `useDraft` 로 막았다. 규칙 1 이 금지한 것은 **서버** 임시 저장이라 `sessionStorage` 를 썼다 — 탭 단위라 공용 PC 에서 남의 초안이 보이지 않는다. **몰래 되살리지 않는다**: 복원했다는 사실과 저장 시각을 알리고 `처음부터 작성` 으로 버릴 길을 준다. 필드 구성이 바뀐 옛 초안은 되살리지 않고 지운다. 저장이 막힌 환경에서도 화면은 뜬다 — 보존은 편의지 필수가 아니다. `run.tsx` 검사 11건 |
| 복구 가능성 | ✅ 오류를 코드별로 나눠 무엇을 고쳐야 하는지 알린다(마감일 3조건을 `DEADLINE_MUST_BE_FUTURE`·`BELOW_MINIMUM`·`EXCEEDS_LIMIT` 로 분리). 빈 목록은 오류가 아니라 안내 + `프로젝트 등록` 버튼으로 다음 행동을 준다. 재모집이 막히면 `notReopenedReason` 으로 사유를 구분해 알린다(규칙 50) |
| 선택권 | ⚠️ **부분.** 수정·마감·취소·삭제·재모집을 사용자가 고를 수 있고, 잠긴 항목도 숨기지 않고 이유와 함께 보여준다. 다만 **AI 추천 예산을 거절하는 경로가 화면에 없다.** 규칙 8 은 분석을 연결하면 사용자 입력 금액을 무시하는데, 그것을 되돌리거나 직접 입력으로 돌아가는 UI 가 없다 |
| 비파괴성 | ✅ **2026-09-02 개선.** 점검에서 `삭제`·`프로젝트 취소` 가 확인 없이 바로 실행되는 것을 발견해 `DestructiveActionSummary` 를 만들어 붙였다. 되돌릴 수 없다는 사실, 어느 프로젝트인지, 함께 일어나는 일(지원자 N건 거절·알림 발송, 합의·계약 무효화, 모집 마감)을 실행 전에 보여준다. 초점은 `그만두기` 에 두고 Esc 로 닫힌다. 되돌릴 수 있는 행동에는 붙이지 않았다 — 전부 확인을 걸면 확인이 무뎌진다. `run.tsx` 검사 12건 |
| 접근 가능성 | ✅ 라벨과 입력을 `htmlFor`/`id` 로 잇고 도움말·오류를 `aria-describedby` 로 연결한다. 오류는 `role="alert"`. 북마크는 `aria-pressed`, 비활성 버튼은 `disabled` 와 문구로 이유를 함께 준다. 상태를 색으로만 구분하지 않는다 — 배지에 항상 글자가 있다. 포커스는 `:focus-visible` 로 보인다. **다만 화면 확대·보조 기술 실측은 아직 안 했다** |

- **트랜잭션이 없다.** 규칙 8 의 롤백을 Mock 에서 `deletedAt` 으로 흉내 냈다.
  실제 구현에서는 트랜잭션 롤백으로 바꿔야 한다.
- **controller 계층이 없다.** HTTP 라우팅·인증 미들웨어는 `app/`(팀장 통합 영역)이다.
  그래서 규칙 49·54 를 여기서 검증할 수 없다.
- **공용 UI 컴포넌트가 없다.** `design-system/` 에 `.tsx` 파일이 없어
  `web/ui.tsx` 에서 직접 만들었다. props 이름과 값 목록은 `design-tokens.md` 와 같게 맞췄으므로
  공용 컴포넌트가 생기면 import 만 바꾸면 된다.
- 상태별 시각 표현(hover·focus·pressed 등 6종)은 CSS 클래스만 두고 실제 스타일은 넣지 않았다.
