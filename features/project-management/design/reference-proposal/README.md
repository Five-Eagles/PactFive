## 지킨 것

**원시 색상값은 `_tokens.css` 의 `:root` 에만 있다.** 화면 3장 본문은 0개다.
`npm run check:design` 통과.

값은 `design-system/design-tokens.md` 정본을 그대로 옮겼다. 변환본이 쓰던
`teal #007a80` · `yellow #ffd735` 는 정본(`#008A8D` · `#F4C430`)과 달라 되돌렸다.

`design-tokens.md` §12 금지 패턴을 따랐다.

- 목적 없는 그라데이션·다색 카드 없음
- 그림자는 두 단계뿐 (`--shadow-card` · `--shadow-raise`)
- 캠페인 색(노랑·자주)은 **기획전 배너 안에서만**
- 반경을 `sm`·`md`·`lg` 로 나눠 모든 영역을 같은 카드로 감싸지 않음
- 마감·손실을 과장하는 문구 없음

썸네일은 사진 대신 **작업물 형태를 그린 SVG** 다. 대시보드·표·브랜드 가이드처럼
실제 결과물로 읽히게 했다. 의미 없는 회색 블록을 두지 않으려는 것이고,
실제 이미지가 준비되면 그 자리에 넣으면 된다.

### 북마크를 헤더에서 마이페이지로

로그인해야 의미가 있는 것이라 비로그인 사용자에게는 누를 수 없는 메뉴였다.

**로그인 화면은 만들지 않았다** — user-management(오민혁) 담당이다.
`demo/session.js` 가 그 자리에 끼울 **연결점**이다. 화면들이 "지금 누가 보는가"를
물어볼 창구 하나뿐이고, 진짜 로그인이 붙으면 `signIn()` 안쪽만 바뀐다.

역할 전환은 남겼다. 역할에 따라 화면이 달라지는 규칙이 여럿이라서다 —
북마크 아이콘(engagement 규칙 30), 내 프로젝트(규칙 17).
자유 입력 폼 대신 **PRD §9.2 시드 계정 6개**를 그대로 세운다.

### 전문가 페이지 — 형식만 제안

PRD 화면 목록에 없는 기능이다. 값은 지어냈지만 **형식은 ERD 에 있는 컬럼만 썼다.**
만들기로 하면 컬럼을 새로 파지 않아도 된다.

| 쓴 것 | 넣지 않은 것 |
|---|---|
| `users` 이름·소개·평점·리뷰 수 | **접속 상태("활동 가능")** — 컬럼이 없다 |
| `freelancer_profiles` 분야·경력·시간당 단가 | **인증 배지** — 컬럼이 없다 |
| `freelancer_skills` 기술 | |

정렬은 평점순·리뷰순·경력순 셋이다. **점수를 만들어 "추천순"이라 부르지 않는다** —
무엇으로 줄 세웠는지 말할 수 없는 순서는 내보내지 않는다.
평가가 없는 사람은 뒤로 보내되 0점으로 취급하지 않는다.

프로필의 행동은 "지원하기"가 아니라 **"프로젝트 등록하고 제안받기"** 다.
이 서비스에서 일은 프로젝트를 통해 오간다 (PRD §5.2). 없는 길을 버튼으로 만들지 않는다.

### 등록 3단계

문구는 `design/high-fi-register.html` 의 「필수 요소 목록」이 정본이다 —
`prototype/run.tsx` 가 기계적으로 확인한다. 여기서 말을 바꾸면 화면과 테스트가 갈라진다.

**입력한 것을 잃지 않는다.** 단계를 오가도, 새로고침해도 남는다.
`sessionStorage` 를 쓴다 — `localStorage` 는 공용 PC 에서 남의 초안이 보인다.

검증은 무엇이 틀렸는지와 **어떻게 고치는지**를 함께 말한다
("5자 이상 입력해 주세요. 지금 2자입니다"). 아직 건드리지 않은 칸에
빨간 글씨를 미리 띄우지 않고, 뒤로 갈 때는 막지 않는다.

### 이용 방법 · 안전한 거래

**내용을 지어내지 않았다.** 흐름·상태·규칙은 PRD §5 와 각 `spec.md` 에 있는 것이다.
문서를 읽은 사람이 화면에서 같은 말을 보게 하는 것이 이 페이지의 일이다.

### 한 링크로 묶기

```bash
node features/project-management/design/reference-proposal/demo/build-bundle.js
```

여덟 화면을 `bundle.html` 한 장으로 묶는다. 해시로 갈아 끼운다.

```text
#/  #/projects  #/detail?id=  #/experts  #/expert?id=  #/mypage  #/register  #/guide
```

묶을 때 **화면마다 CSS 를 `.route-<이름>` 안으로 가둔다.** 파일이 따로일 때는
`.filters` 가 겹쳐도 문제가 없었는데, 한 파일로 합치면 나중에 실린 쪽이 이긴다 —
프로젝트 목록의 필터 패널이 전문가 목록의 것으로 바뀐다.

확인: 여덟 화면 모두 죽은 링크 0개 · 1400px 과 375px 에서 가로 넘침 0px · 콘솔 오류 없음.

## 2026-09-03 — 시안이 실제로 동작한다

정적 HTML 이라 아무 버튼도 눌리지 않았다. 세 화면 전부 동작하게 고쳤다.

### 어떻게 열어 보나

```bash
npx serve .          # 리포 루트에서
```

`features/project-management/design/reference-proposal/main.html` 로 들어가면
세 화면이 링크로 이어진다. 한 파일로 묶으려면:

```bash
node features/project-management/design/reference-proposal/demo/build-bundle.js
```

CSS·사진·스크립트를 전부 넣은 `bundle.html` 한 장이 나온다. 서버 없이 열린다.

### 구조

| 파일 | 무엇 |
|---|---|
| `demo/data.js` | PRD §9 시드 P01~P12. 마감일은 오늘 기준 상대 일수 |
| `demo/engine.js` | `spec.md` 규칙을 화면에서 그대로 돌린다. 주석에 규칙 번호를 붙였다 |
| `demo/bookmarks.js` | engagement 규칙 1·2 멱등 토글 |
| `demo/notyet.js` | 아직 없는 화면을 눌렀을 때의 안내 |
| `demo/build-bundle.js` | 세 화면을 한 파일로 묶는다 |

### 동작하는 것

| 무엇 | 확인한 결과 |
|---|---|
| 검색 (기술 이름) | `React` 2건 · `Figma` 3건 |
| 검색 (두 낱말 AND) | `관리 페이지` 1건 |
| 카테고리 10종 | 각 타일이 실제로 걸러진 목록으로 간다 |
| 기술 필터 AND | 웹 개발 4건 → +React 2건 → +SQL 1건 |
| 예산 범위 · 마감 포함 | 8건 → 12건 |
| 정렬 3종 | 예산 높은순 1위 18,000,000원 · 마감임박순 1위 홍보 영상 제작 |
| 페이지 | 12건 / 9 = 2페이지 |
| 필터 초기화 | 검색어와 정렬을 남긴다 (규칙 61) |
| 빈 결과 | "조건 모두 지우기"를 함께 준다 |
| 카드 → 상세 | 제목을 누르면 그 프로젝트로 |
| 상세 추천 4건 | engagement 규칙 18~24. 무엇이 겹쳤는지 말하고 점수는 안 보인다 |
| 지원 버튼 | 모집 예정·마감이면 막고 **이유를 말한다** |
| 북마크 | 몇 번을 눌러도 결과가 같다. 같은 카드가 여러 곳이면 전부 같이 바뀐다 |
| 내 북마크 | 저장한 것만 모아 본다. 비어 있으면 둘러보기로 안내 |
| 기획전 슬라이드 | 3장. 자동으로 넘기지 않는다 |
| 없는 화면 버튼 | 없다는 것 + **담당자와 명세 위치**를 말한다 |

**아직 없는 화면은 링크를 죽여 두지 않았다.** `href="#"` 로 두면 눌러도 아무 일이
없어 고장으로 읽힌다. 무엇이 없고 누가 만들며 명세가 어디 있는지까지 말한다 —
시안을 보는 사람이 곧 그 화면을 만들 사람이기 때문이다.

### 조건은 주소에 남는다

`#keyword=React&category=WEB_DEVELOPMENT&page=2` 처럼 해시에 담는다.
뒤로 가기가 동작하고, 걸러 놓은 화면을 링크로 넘길 수 있다.

물음표가 아니라 해시인 이유: 정적 파일이라 서버가 없고, 해시는 `file://` 에서도
미리보기 도구에서도 그대로 살아남는다.

### 이 규칙들은 서버에도 있다

`demo/engine.js` 는 `prototype/server/project.service.ts` 와 **같은 판정을 두 번**
한다. 시안이 서버 없이 돌아야 해서다. 그래서 주석에 규칙 번호를 붙였다 —
나중에 둘이 어긋나면 어디를 봐야 하는지 알 수 있다.

## 2026-09-03 원본 복원 — 걷어낸 것을 되돌린다

### 무엇을 잘못했나

`ux-philosophy/reference-main.html` 을 **렌더링해서 보지 않고** grep 으로 구조만 읽고
작업했다. 그 파일에는 base64 로 사진 5장이 박혀 있는데 그걸 놓쳤고, 그래서
"근거 없는 장식"으로 판단해 걷어낸 것들이 사실은 시안의 핵심이었다.

**되돌린 것**

| 항목 | 상태 |
|---|---|
| 기획전 배너 (자주색 뒤판 + 노란 배너 + 사진) | 복원. 실제로 넘어가는 슬라이드로 만들었다 |
| 인기 검색 키워드 5종 | 복원. 각각 목록 검색으로 이어진다 |
| 내 프로젝트 요약 줄 (파일 · 진행 단계 · 마감일) | 복원 |
| 카테고리 10종 + "인기" 배지 | 복원. 다색 아이콘 그대로 |
| 추천 전문가 4장 (사진 · 인증 · 활동 가능) | 복원 |
| 히어로 검색창 · "전문가 찾기" | 복원 |
| 4단 네비 (프로젝트 찾기 · 전문가 찾기 · 이용 방법 · 안전한 거래) | 복원 |

### 사진은 파일로 꺼냈다

시안은 사진 5장을 base64 로 HTML 안에 넣어 파일이 147KB 다. 그러면 diff 를 볼 수 없다.
`assets/` 로 꺼내 참조한다 (2026-09-02 팀장이 정한 기능 폴더 assets 관례).

```text
assets/banner-b2b.jpg          44KB   기획전 배너
assets/expert-dashboard.jpg    11KB   김다은 작업물
assets/expert-backoffice.jpg   12KB   박서윤 작업물
assets/expert-branding.jpg     17KB   이준호 작업물
assets/expert-content.jpg      13KB   최유진 작업물
```

### 시안에서 바꾼 것은 셋뿐이다

**1. 색값을 정본 토큰으로.** 본문에 원시 색상값 0개.
시안의 다색 아이콘 팔레트는 `_tokens.css` 에 `--ico-*` 로 선언해 그대로 살렸다.
별점 색도 `--rating-star` 로 뒀다 — 노랑 계열이지만 캠페인 색도 경고 색도 아니다.

**2. 배너를 실제 슬라이드로.** 시안은 "1 / 5" 가 표시만이고 넘어가지 않았다.
3장으로 만들고 점·화살표·좌우 방향키로 넘어가게 했다.
**자동으로 넘기지 않는다** — 읽는 속도를 화면이 정하면 안 되고, 자동 전환은
스크린리더 사용자에게 특히 불친절하다. 보이지 않는 슬라이드는 `inert` 로 탭 순서에서 뺀다.

**3. 반응형.** 시안은 `min-width:1180px` 고정이라 그 아래가 정의돼 있지 않았다.
1280 / 1024 / 768 / 360 을 채웠다. 네 폭 모두 가로 넘침 0px.

### 더한 것 하나

"지금 모집 중인 프로젝트" 6장. 이 화면에서 **실제 API 로 채워지는 유일한 자리**다
(`GET /api/v1/projects`). 샘플은 PRD §9 시드 P01~P05·P12 를 그대로 썼다.

## 확인이 필요한 것

시안을 살리면서 **데이터 근거가 없는 부분은 지우지 않고 여기 적어 둔다.**
지우는 판단을 제가 임의로 하지 않는다.

| 항목 | 무엇이 없나 | 누가 정해야 하나 |
|---|---|---|
| **추천 전문가** | PRD 화면 목록(§7.1)에 프리랜서 탐색이 없다. 담당자도 없다 | 팀장 · 오민혁 |
| **"전문가 찾기" 네비** | 위와 같다 | 팀장 |
| **기획전 배너** | 배너를 담을 테이블이 ERD 에 없다. 지금은 화면에 고정돼 있다 | 팀장 |
| **인기 검색 키워드** | 검색 로그 테이블이 없다. 지금은 고정 5개다 | 팀장 |

## 2026-09-02 재정리 — 검색을 필터로, 바탕을 노랑으로

### 왜 검색을 뺐나 — 실측

통합 앱에서 API 를 직접 두드려 확인했다.

| 입력 | 결과 |
|---|---|
| `keyword=React` | **0건** |
| React 를 요구 기술로 가진 프로젝트 | **1건 있다** (패션 커머스 리뉴얼) |
| `keyword=정산` | 1건 — 설명에 그 단어가 있어 걸림 |

`keyword` 는 **제목과 설명만** 본다 (PRD §3.6). 사람들이 검색창에 먼저 치는 것은
기술 이름인데 그건 `skills` 필터가 맡는다. **"React" 를 치면 빈 화면이 나온다.**

그래서 히어로의 검색창을 **조건 필터 3종**으로 바꿨다.

| 칸 | 쿼리 파라미터 | 근거 |
|---|---|---|
| 기술 | `skills` | PRD §3.6 · 공식 기술 12종 |
| 예산 | `minBudget` · `maxBudget` | PRD §3.6 |
| 마감 | `deadlineBefore` | PRD §3.6 |

셋 다 `GET /api/v1/projects` 가 실제로 받는 조건이다. 없는 필터를 만들지 않았다.

**카테고리는 아래 타일이 맡는다** — RFP §3.2.2 의 "메인 페이지 카테고리 버튼"이다.
히어로 필터와 겹치지 않게 나눴다.

> 키워드 검색 자체를 없앤 것은 아니다. 목록 화면(`browse.html`)의 필터 패널 안에
> 그대로 남는다. RFP §3.2.2 가 `keyword` 를 요구하기 때문이다.
> 바꾼 것은 **대표페이지의 첫 입력이 무엇이냐**다.

### 색의 역할을 정했다

청록 하나로 바탕까지 칠하다 보니 화면이 청록으로 도배됐다. 역할을 셋으로 갈랐다.

| 색 | 역할 | 쓰는 곳 |
|---|---|---|
| **노랑** | 바탕과 포인트 | 히어로 판 · 단계 번호 · AI 제안 금액 표시 |
| **청록** | 행동 | 버튼 · 링크 · 선택 상태 · 모집 중 배지 · 북마크 |
| **남색** | 정보 | 글자 · 카테고리 아이콘 · 테두리 |

**청록을 바탕에 쓰지 않는다.** 바탕까지 청록이면 버튼이 눈에 띄지 않는다.

카테고리 아이콘을 청록에서 남색으로 옮긴 것이 가장 큰 변화다. 6개가 나란히 청록이면
그것만으로 화면이 청록으로 덮인다.

`_tokens.css` 에 노랑 3단계를 추가했다.

```css
--campaign-yellow-soft: #FDF3D6;   /* 히어로 바탕 */
--campaign-yellow-edge: #EFDFAA;   /* 그 위의 경계선 · 뒤판 */
--campaign-yellow-deep: #E8C765;   /* 두 번째 뒤판 */
```

amber 계열(`--amber-50`)을 쓰지 않은 이유는 그쪽이 경고(`--warning-surface`)에
배정돼 있어서다. 같은 색이 두 가지 뜻을 가지면 안 된다.

### 슬라이드 — 사용법 3단계

걷어낸 기획전 배너 대신 **서비스 사용법**을 슬라이드로 넣었다. 데이터가 필요 없고,
첫 방문자가 "여기서 무슨 일이 일어나는가"를 바로 안다.

```text
1  프로젝트 등록    AI 단가 분석이 예산 범위를 먼저 알려준다
2  지원과 수락      지원자를 나란히 놓고 고른다
3  계약과 정산      합의 금액이 계약서가 되고, 납품 승인 뒤에 정산된다
```

번호를 붙인 이유는 **순서가 실제 정보이기 때문**이다. 등록해야 지원이 오고,
수락해야 계약이 열린다. 장식이 아니다.

**자동으로 넘기지 않는다.** 읽는 속도를 화면이 정하면 안 되고, 자동 전환은 스크린리더
사용자에게 특히 불친절하다. 점·화살표·좌우 방향키로만 넘어간다.
보이지 않는 패널은 `inert` 로 탭 순서에서 뺀다 — 안 그러면 화면 밖으로 포커스가 간다.
`prefers-reduced-motion` 이면 전환이 0ms 다.

### 측정

| | 걷어내기 전 | 걷어낸 직후 | 겹 고도화 | 지금 |
|---|---|---|---|---|
| 데스크톱 전체 높이 | 2,391px | 1,564px | 1,879px | **2,215px** |
| 375px 첫 카드 y | 1,231px | 866px | 1,246px | **1,401px** |
| 360px 가로 넘침 | — | 0 | 0 | **0** |
| 근거 없는 요소 | 6종 | 0종 | 0종 | **0종** |

높이가 다시 는 것은 슬라이드 3단계가 들어간 값이다. 걷어낸 6종은 돌아오지 않았다.

모바일에서는 필터를 2열로 두고(3열이면 칸이 좁고, 1열이면 세 줄이 되어 히어로가 화면
하나를 더 먹는다) 슬라이드를 프로젝트 목록 **뒤로** 보냈다.

## 2026-09-02 고도화 — 겹으로 두께를 만든다

걷어내고 나니 화면이 휑해졌다는 지적을 받았다. 맞는 지적이다 — 히어로 오른쪽이 비었고,
아이콘이 1.8px 선 하나뿐이라 성의 없어 보였다.

**허구를 다시 채우지 않고 두께로 채웠다.**

### 겹의 규칙

포인트가 되는 면은 세 겹으로 쌓는다.

| 겹 | 무엇 | 어떻게 |
|---|---|---|
| 1 판(plate) | 뒤로 물러난 연한 면 | 위치를 어긋나게 둔다. 겹이 보여야 한다 |
| 2 표면(face) | 내용이 올라가는 흰 면 | 테두리 + 위쪽 1px 밝은 선(`--edge-top`) |
| 3 부양(lift) | 앞으로 떠 있는 조각 | 접지 그림자 + 확산 그림자 |

**그림자만 키우지 않는다.** 흐려지기만 하고 두께로 읽히지 않는다 (§12).
어긋난 위치 · 테두리 · 위쪽 밝은 선이 함께 있어야 면으로 보인다.

### 히어로 삽화 — 제품 자체를 그린다

오른쪽에 다시 그림을 넣되, **없는 기능·없는 데이터를 그리지 않는다.**
걷어낸 기획전 배너 대신 **이 서비스의 목록 화면 자체**를 그렸다.

```text
1겹  연한 청록 뒤판 두 장 — 어긋나게 겹친다
2겹  목록 패널 — 검색창 · 정렬 3종 · 프로젝트 행 3개
3겹  떠 있는 카드 — 실제 카드와 같은 9개 정보 그룹
```

글자는 **실제로 화면에 나오는 문구**를 쓴다. 의미 없는 회색 막대를 늘어놓지 않았다.
떠 있는 카드가 목록 3번째 행을 일부 가린다 — 가려짐이 그림자보다 깊이를 잘 만든다.

### 아이콘 — 선 하나에서 세 겹으로

| | 전 | 후 |
|---|---|---|
| 구성 | 1.8px 선 하나 | **연한 판 + 중간 채움 + 진한 선** |
| 담는 곳 | 배경색 사각형 | **어긋난 판 + 흰 표면 + 위쪽 밝은 선** |
| 크기 | 22px | 26px (그릇 48px) |

담는 그릇은 `::before`(판) → `::after`(흰 표면) → `svg`(글리프) 순으로 쌓았다.
`::before` 하나로 하면 부모 배경 위에 얹혀서 표면을 덮는다 — 판이 뒤로 가지 않는다.

카테고리 타일 자체도 카드가 됐다. hover 에 `translateY(-2px)` 를 준다 (피드백 100ms).

### 그림자 단계를 하나 늘렸다

`--shadow-hero` 를 `_tokens.css` 에 추가했다. **히어로 삽화 한 곳에만 쓴다.**
§12 가 금지하는 것은 카드 격자에서 흰 카드를 띄우려고 그림자를 키우는 것이고,
겹쳐 놓은 판을 분리하는 것은 다른 문제다. 목록 카드는 여전히 `--shadow-card` 다.

### 검색을 이어붙였다

대표페이지 검색창이 `browse.html?keyword=…` 로 값을 넘기고, 목록 화면이 그 값을 받아
검색란을 채운다. 넘긴 값이 사라지면 사용자가 다시 입력해야 한다.

시안이라 실제 필터링은 하지 않는다. **통합 앱에서는 이미 동작한다** —
`GET /api/v1/projects?keyword=` 가 제목과 설명에서 찾고, 조건이 바뀌면 1페이지로 돌아간다.

### 측정

| | 걷어내기 전 | 걷어낸 직후 | 지금 |
|---|---|---|---|
| 데스크톱 전체 높이 | 2,391px | 1,564px | **1,879px** |
| 375px 첫 카드 y | 1,231px | 866px | **1,246px** |
| 360px 가로 넘침 | — | 0px | **0px** |
| 근거 없는 요소 | 6종 | 0종 | **0종** |

높이가 다시 는 것은 삽화를 넣은 대가다. 늘어난 315px 이 전부 삽화이고,
걷어낸 6종은 돌아오지 않았다.

모바일 검색은 두 줄로 쌓지 않고 한 줄로 뒀다 — 쌓으면 첫 카드가 56px 더 밀린다.
360px 에서 버튼 121px + 입력 199px 로 들어간다.

## 2026-09-02 정리 — 근거 없는 것을 걷어냈다

팀에서 "PRD 필수 스펙 외에는 걷어내자"는 이야기가 나와 `main.html` 을 한 번 훑었다.

### 먼저 확인한 것 — 검색은 뺄 수 없다

### 걷어낸 것 6종

| `예상 기간` | `applications.expected_duration_days` — **지원자가 제시하는 값**이다 | 제외. 프로젝트에는 없다 |

`projects` 컬럼을 전부 확인했다. 근무 방식은 없고, 예상 기간은 지원서 필드라
프로젝트 카드에 넣으면 "누구의 예상인가"가 성립하지 않는다.

**대신 `projects`·`ClientPublicProfile` 에 실제로 있는 값으로 채웠다** —
카테고리, 의뢰인 평점·리뷰 수, 마감 절대 날짜. 전부 `PublicProjectItem` 이 이미 내려보내는 값이다.

### 여백 — 외곽은 그대로 두고 내부만

조사 결론대로 패딩 24px · gap 16px · 반경 14px 은 **바꾸지 않았다** (레퍼런스 범위 안).
줄인 것은 카드 내부 row gap(12→8px)과 히어로 상하 여백이다.

카드 높이는 321 → 328px 로 오히려 7px 늘었지만, 정보가 6개에서 9개로 늘어
**정보 1개당 56px → 36px** 이 됐다. 국내 프로젝트형(17~27px)에는 아직 못 미치고
크몽 4열 카드(38~57px)보다는 촘촘하다.

### 모션 — 정본 유지

## 처음 만들 때 바꾼 것 — 확인이 필요하다

**카테고리를 10종에서 6종으로 줄였다.** PNG 시안의 10종(브랜딩·영상·사진·콘텐츠 등)은
ERD `projects.category` 에 없는 값이다. 그대로 두면 누를 수 없는 메뉴가 된다.
카테고리를 늘릴지, 화면을 6종으로 둘지 정해야 한다.

**필터를 버튼이 아니라 상시 패널로 뒀다** (`browse.html`).
시안의 `필터` 버튼은 열릴 화면이 정의돼 있지 않다 (feedback_loop 2026-08-28 항목 6).
패널로 두면 무엇으로 거를 수 있는지가 항상 보이고, 별도 화면을 설계하지 않아도 된다.
