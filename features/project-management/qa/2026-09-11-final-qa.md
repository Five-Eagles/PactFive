| | |
|---|---|
| 담당 | 유동우 |
| 실행 | 2026-09-11 |
| 환경 | 배포 사이트 `pact-five-seven.vercel.app` (최신 develop · #110 반영 확인) · 실제 시드 계정 |

---

## 1. 왜 보기만 했나

배포 서버는 팀 전체가 같은 데이터를 쓴다. 예를 들어 시드 프로젝트를 마감하면 거기 지원해 둔
프리랜서 시드 계정의 지원이 자동 거절되고 알림이 나간다 — 다른 담당자의 QA 상태가 깨진다.

등록·수정·마감·재모집처럼 데이터를 바꾸는 흐름은 2026-09-10 에 로컬에서 따로 만든 데이터로
서버 응답과 화면을 이미 확인했다(`2026-09-10-qa-result.md`). 이번에는 **실제 계정으로 같은 화면이
나오는지**만 봤다.

---

## 2. 확인한 것

### 비로그인

| 확인 | 결과 |
|---|---|
| 프로젝트 목록 · 카드 전체 클릭 → 상세 | 통과 |
| 상세: 마감 표시 · "평가 없음 · 리뷰 0건" · 지원하기 · 북마크 | 통과 |
| 북마크 누르면 로그인 화면으로 | 통과 (돌아오기는 3절 ②) |

### 의뢰인 · 모집 중 (`seed.client.recruiting`)

| 확인 | 결과 |
|---|---|
| 내 프로젝트 요약 문구 | "지원 1건 · 마감 30일 전", 계약 대기는 "선정된 프리랜서와 금액 합의 중" |
| 버튼 — 계약 대기 | 취소만 켜짐. 수정·마감·삭제·재모집 꺼짐 |
| 버튼 — 지원 0건 | 수정·마감·취소·삭제 켜짐 |
| 버튼 — 대기 지원 있음 | 삭제 꺼짐 (규칙과 일치) |
| 상세 (본인) | "지원 1건 · 대기 1건", 지원 버튼 없음 |
| 상세 (계약 대기) | 배지 "모집 마감 · 계약 대기", 머리 "모집 마감" |
| 수정 화면 (지원자 있음) | "지원자 1명이 있어 예산과 일정은 변경할 수 없습니다." · 예산·일정 읽기 전용 · 제목·설명은 수정 가능 |
| 새로고침·다른 탭 | 로그인 유지 |

### 의뢰인 · 마감 (`seed.client.closed`)

| 확인 | 결과 |
|---|---|
| 내 프로젝트 요약 문구 | "지원 1건 · 마감일이 지났습니다" — 9/10 에 고친 두 문구가 실제 데이터로도 맞게 나온다 |
| 배지 | "모집 마감 · 재모집 가능" |
| 버튼 | 수정·마감 꺼짐 / 취소·삭제·다시 모집하기 켜짐 |
| 상세 머리 | "모집 마감" (마감 N일 전 안 붙음) |

### 확인하지 않은 것

프리랜서 계정의 북마크 저장·해제는 배포 사이트에서 다시 누르지 않았다. 누르면 공용 시드 계정의
데이터가 바뀐다. 9/10 로컬 QA 에서 저장↔해제, 마감된 프로젝트가 목록에 남는 것까지 확인했다.

## 3. 다른 영역에서 본 것 — 4건

내 기능 밖이라 고치지 않았다. 담당 쪽에서 판단하면 된다.

| # | 어디서 | 무엇이 | 원인으로 보이는 곳 |
|---|---|---|---|
| ① | 로그인 화면 | 로그인하지 않은 사람이 열면 "세션이 만료되었습니다."가 먼저 뜬다. 비밀번호를 틀리면 "이메일 또는 비밀번호가 올바르지 않습니다."가 잠깐 보였다가 곧바로 "세션이 만료되었습니다."로 덮인다 | 로그인 요청의 401 이 전역 401 처리를 타서 로그인 화면이 새로 불리고, 앱 시작 시 세션 복원 실패 문구가 남는다 (`user-management/api/auth.ts` createAuthSession · `shared/http.ts`) |
| ② | 북마크 → 로그인 | 로그인한 뒤 원래 보던 프로젝트로 돌아오지 않는다 | `App.tsx` 의 `onRequireLogin` 이 돌아올 주소 없이 `/login` 으로만 보낸다 |
| ③ | 상단 메뉴 | 로그아웃 버튼이 메인 화면에만 있고 다른 화면 상단에는 없다 | 공통 상단 메뉴 (`AppShell`) |
| ④ | 로그아웃 | 화면은 로그아웃되지만 서버 요청 `DELETE /api/v1/auth/sessions/current` 가 **503** 이었다 | user-management 서버 |
