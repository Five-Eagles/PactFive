함수별 필수 정의 확인 요청 — 유동우

수신: 유동우 (project-management) · 발신: 조준영 (contracts-payments) · 2026-08-25
정본: PRD v6.4 §5.4 · ERD v1.4 · spec.md · 목적: 네 함수의 필수 정의사항을 예/아니오로 확정

이미 「예」로 닫힌 멱등 키·버전 비증가·D-43은 다시 묻지 않습니다. 조준영이 동의한 내부 경로·notReopenedReason·버전 필수는 맨 아래 재확인만 받습니다.

참고 — 다시 묻지 않는 합의

항목상태
멱등 키 transaction-start-{contractId} / transaction-complete-{contractId}유동우 예
markPaymentPending 버전 비증가유동우 예
D-43: 200 + 모집 재개만 보류유동우 예
내부 주소 5개 유동우가 만듦유동우 예
/internal/v1/... · notReopenedReason · start/complete 버전 필수조준영 동의, 재확인

1. startProjectTransaction

반드시 확정: 호출 주체, 수락된 지원 ID, 프로젝트 시작 상태

항목현재 초안
호출 주체조준영 → 유동우. SIGNED 그리고 PAID 직후 1회
수락된 지원 ID요청 본문에 없음. C-01이 심은 accepted_application_id를 조회로만 확인
시작 상태CONTRACT_PENDING → IN_PROGRESS (모집 CLOSED)
#질문예아니오대안
S1호출 주체는 조준영 서버만이고, 브라우저·의뢰인 직접 호출은 거부하는가
S2start 요청에 acceptedApplicationId를 넣지 않고 프로젝트 컬럼만 믿는가
S3조회 응답의 acceptedApplicationId가 null이면 start를 409로 거부하는가
S4허용 시작 상태는 CONTRACT_PENDING뿐이며 성공 후는 IN_PROGRESS인가

2. completeProjectTransaction

반드시 확정: 완료 조건, 완료 권한, 중복 완료 처리

항목현재 초안
완료 조건호출자가 APPROVED ∧ RELEASED를 지킴. 유동우는 IN_PROGRESS만 검사
완료 권한내부 계약만. 사용자 로그인 토큰 불가
중복 완료이미 COMPLETED면 200. CANCELED면 409
#질문예아니오대안
C1납품·정산 테이블을 읽지 않고 IN_PROGRESS만 보고 전이하는가
C2완료는 조준영 서버만, 공개 API로는 열지 않는가
C3이미 COMPLETED 재호출은 200 멱등인가
C4CANCELED에서 complete는 409인가

3. restorePreContractProject

반드시 확정: 복원 대상 상태, 합의·계약 취소와의 관계

항목현재 초안
복원 대상transactionStatus → NONE. 조건부 모집 OPEN. 제목·설명 보존
합의·계약이 함수는 합의·계약을 취소하지 않음. invalidateAgreementAndContract와 반대 방향·다른 사건
#질문예아니오대안
R1건드리는 필드는 거래 상태와 (조건부) 모집 상태뿐인가
R2restore가 합의 REJECTED·계약 CANCELED를 대신하지 않는가
R3프로젝트 취소와 restore를 같은 경로로 처리하지 않는가
R4자동 거절된 지원자를 되살리지 않는가

4. markPaymentPending

반드시 확정: 결제 대기 전환 조건, 결제 식별정보 포함 여부

항목현재 초안
전환 조건CONTRACT_PENDING + 미취소. PG 직전. 상태는 안 바꾸고 paymentPendingAt만
식별정보본문에 paymentId/contractId 없음. 멱등 키만 payment-pending-{contractId}
#질문예아니오대안
P1허용 조건은 CONTRACT_PENDING + 미취소뿐인가
P2본문에 결제·계약 ID 없이 멱등 키만으로 충분한가
P3본문에 contractId 명시 필드가 필요한가 (초안은 아니오)
P4이미 paymentPendingAt이면 200, 시각은 최초값 유지인가

함께 정할 3건 — 구현 측 재확인

#내용예아니오메모
J1경로 /internal/v1/projects/:projectId/...
J2notReopenedReason: null / DEADLINE_PASSED / PENDING_APPLICATIONS_REMAIN
J3start와 complete만 expectedProjectVersion 필수

ERD project_version 주석 정정은 김락원 담당, change-request로 남깁니다.
