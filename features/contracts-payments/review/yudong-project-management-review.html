1. startProjectTransaction — 가장 먼저 확정

조준영 → 유동우. 계약 SIGNED 그리고 결제 PAID 직후 1회. 선행: 최윤석 acceptProjectApplication → CONTRACT_PENDING. 호출 전 getProjectNegotiationContext 의무 (D-44).

항목계약
경로POST /api/v1/projects/:projectId/start-transaction
실행 전CONTRACT_PENDING
실행 후IN_PROGRESS (모집 CLOSED 유지)
중복이미 IN_PROGRESS면 200. CANCELED면 재시도도 409
판정 순서존재 → 멱등 키 → 이미 IN_PROGRESS → 그 외 상태 → 버전 → 전이
멱등 키제안: transaction-start-{contractId}

3. markPaymentPending

PG 요청 직전. 경로 POST .../mark-payment-pending. 멱등 키 payment-pending-{contractId}. 거래/모집 상태는 바꾸지 않는다. 이미 paymentPendingAt이 있으면 200.

ASSUMPTION: projectVersion을 올리지 않음 (상태 전이가 아님).
{ "projectId": "prj_123", "transactionStatus": "CONTRACT_PENDING",
  "paymentPendingAt": "2026-08-25T05:00:00Z",
  "alreadyProcessed": false, "processedAt": "2026-08-25T05:00:00Z",
  "changed": true, "projectVersion": 7 }

4. completeProjectTransaction

APPROVED ∧ RELEASED 직후. 전 IN_PROGRESS → 후 COMPLETED. 이미 COMPLETED면 200. 멱등 키 제안 transaction-complete-{contractId}.

{ "projectId": "prj_123", "recruitmentStatus": "CLOSED", "transactionStatus": "COMPLETED",
  "alreadyProcessed": false, "processedAt": "2026-08-25T06:00:00Z",
  "changed": true, "projectVersion": 9 }

5. restorePreContractProject

최신 제안 수신자의 최종 거절만. 입력: negotiationId(필수), offerId(선택), actorUserId, reason(FREELANCER_REJECTED | CLIENT_REJECTED). 멱등 키 negotiation-reject-{negotiationId}. §5.7 agreementId는 D-55로 폐기.

실행 후 transactionStatus → NONE. 마감 남고 대기 지원 0이면 OPEN + reopened: true. 마감 지남 또는 대기 지원 잔존이면 CLOSED + reopened: false (200). 대기 지원이 있으면 유동우가 최윤석에게 rejectPendingApplications를 재요청한다 (D-43). 같은 negotiationId는 200, 다른 협상은 409 PROJECT_ALREADY_RESTORED.

{ "projectId": "prj_123", "negotiationId": "ngt_123",
  "recruitmentStatus": "OPEN", "transactionStatus": "NONE", "reopened": true,
  "restoredFields": ["recruitmentStatus", "transactionStatus"],
  "alreadyProcessed": false, "processedAt": "2026-08-25T04:30:00Z",
  "changed": true, "projectVersion": 8 }
