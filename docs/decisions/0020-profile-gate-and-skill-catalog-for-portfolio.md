# 프로필 게이트는 화면 유도 방식 유지, 기술 목록은 PRD 32종으로 맞춘다

| 항목 | 내용 |
|---|---|
| 상태 | **초안 — 팀 확인 대기** (2026-10-01, 포트폴리오 정리 중 Claude가 추천안대로 구현. 팀장 위임) |
| 범위 | RFP §3.1.3 프로필 완성 유도, PRD v6.6 §8.2 기술 스택 목록 |
| 관련 | ADR-0014(프로필 게이트 경고 모드), user-management spec PC-01~08, ERD E-14/E-15 |

## 왜 이 문서를 읽어야 하는가 (Context)

포트폴리오 정리 계획(B안)에서 "명세와 제품이 어긋난 곳"으로 두 가지가 나왔다.
프로필 게이트가 꺼져 있다는 9/22 QA 기록(A-02)과, 기술 목록이 PRD와 다르다는 점이다.

## 1. 프로필 게이트

### 사실 (Fact)

- RFP §3.1.3: 등록·지원 시점에 필수 프로필이 비어 있으면 **프로필 입력 페이지로 유도한 뒤 원래 액션으로 복귀**.
- 웹에는 이미 유도 장치가 있다. `App.tsx`의 `ProfileGatedRegister`·`ProfileGatedApply`가
  `GET /profiles/me`의 `complete`가 false면 `/profile?returnTo=...`로 보내고, 저장 후 원래 화면으로 돌려보낸다.
- 그런데 프로필 저장이 한 번도 성공하지 못해(운영 DB 프로필 0건, 커밋 37d7d13에서 수정)
  유도 장치가 사실상 "빠져나올 수 없는 고리"였다.
- 9/22의 "A-02 켜지 말 것"은 **서버가 지원 API 자체를 막는 차단**(`PROFILE_INCOMPLETE`)을 말한다. ADR-0014가 "경고만, 지원 허용"으로 정했다.

### 결정 (초안)

- **화면 유도 방식을 그대로 쓴다.** 저장 버그가 고쳐졌으므로 RFP의 "유도 후 복귀"가 이제 동작한다.
- **서버 차단은 계속 끈다(ADR-0014 유지).** 데모에 필요하지 않고, 켜면 프로필 조회 실패 시 지원 전체가
  503이 되는 경로가 생긴다.
- **바뀔 수 있는 조건** — 외부 API 사용자가 화면을 거치지 않고 지원하는 것을 막아야 할 때 서버 차단을 켠다.

## 2. 기술 목록

### 사실 (Fact)

| 위치 | 이전 | 문제 |
|---|---|---|
| PRD v6.6 §8.2 (정본) | 32종 | — |
| DB `skills` | 12종 | PRD 24종 없음 |
| 서버 검증 `in-memory-external.adapter.ts` | 12종 | PRD에 없는 SPRING·FIGMA·FLUTTER·AWS 포함 |
| 등록 화면 `SKILL_OPTIONS` | 6종 | 대부분 선택 불가 |

### 선택지

| 안 | 장점 | 단점 |
|---|---|---|
| A. 세 곳 모두 PRD 32종으로 | 명세와 제품 일치 | 기존 데이터의 4종 처리 필요 |
| B. 12종 유지, PRD를 12종으로 개정 | 코드 변경 없음 | 디자인·마케팅·기획 프로젝트를 등록할 수 없음 |

### 결정 (초안): A안

- 서버·시드·웹을 PRD 32종으로 맞췄다. 웹은 그룹(프론트엔드·백엔드·…)별로 보여준다.
- 이전 4종(SPRING·FIGMA·FLUTTER·AWS)은 기존 프로젝트 97건의 연결 데이터 때문에 **서버가 계속 인정하지만
  새 선택지에는 없다.** PRD 기준으로는 각각 JAVA·UI_UX_DESIGN·CROSS_PLATFORM·CLOUD에 통합된다.
- **운영 DB 반영에 필요한 일**: 배포 전에 `npm run seed:skill-catalog` 1회 실행(멱등, 기존 행은 건드리지 않음).

## 확인

- 서버·웹 타입 검사 통과, 통합 테스트 35건 PASS.
- 골든 패스 점검 22단계 PASS (프로젝트 기술에 PRD 신규 코드 `CLOUD` 포함).
