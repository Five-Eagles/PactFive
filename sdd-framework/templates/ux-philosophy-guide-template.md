# UX 철학 문서 가이드 (UI·UX 담당자용)

이 문서는 UX 철학 문서를 무엇으로, 어떻게 산출해야 하는지 정의하는 가이드입니다. 완성된 UX
철학 자체가 아니라 "이렇게 써라"는 지침입니다. 디자인 시스템 가이드(`design-system-guide-
template.md`)와 짝을 이루지만, 산출물은 서로 독립적입니다 — 디자인 시스템의 특정 컴포넌트가
바뀌어도 이 문서는 바뀌지 않아야 합니다.

## 1. 참고해야 할 입력 자료

- 확정된 디자인 시스템 (`design-system/design-tokens.md`, `-preview.html`) — 톤앤매너 참고용
- 확정된 프로젝트 컨셉 (`pactfive_design_concept_discussion.html`에서 정한 방향, 예:
  "Trust by Evidence")
- 대표 UI 화면 1~2개 (있다면 — 없어도 작성 가능)

## 2. 핵심 규칙 — 추상 수준을 유지한다

**이 문서는 특정 UI 컴포넌트와 결합되면 안 됩니다.** 디자인 시스템의 컴포넌트가 통째로
바뀌어도(예: Button 컴포넌트 라이브러리 교체) 이 문서의 원칙은 그대로 유지되어야 합니다.

- 금지: "Badge 컴포넌트를 amber-50 배경에 표시한다" 처럼 구체적 컴포넌트명·색상 hex·px 값을
  직접 인용하는 서술
- 권장: "사용자가 대기 상태에 있을 때는 항상 그 사실과 다음 행동을 함께 보여준다" 처럼, 어떤
  컴포넌트로 구현하든 성립하는 원칙 레벨 서술
- 예시가 필요하면 넣되, "이것은 현재 구현의 한 예시일 뿐 원칙 자체가 아니다"라고 반드시
  라벨링합니다.

## 3. 문서 구성

1. **핵심 철학 한 문장** — 프로젝트 컨셉에서 그대로 이어지는 한 줄 (예: "상태·시간·근거·다음
   행동으로 신뢰를 증명한다")
2. **왜 이 철학인가** — 프로젝트 컨셉·타깃 사용자와의 연결 (Fact/Opinion 구분해서 서술)
3. **원칙 3~5개** — 각 원칙은 "무엇을 보장해야 하는가"로 서술합니다. 구체적 컴포넌트 언급 없이,
   어떤 화면에도 적용 가능한 수준으로 씁니다.
4. **원칙별 적용 예시 (옵션)** — 현재 디자인 시스템 기준 예시 1개씩. "예시" 라벨을 명확히 답니다.

## 4. 산출물 (2가지, 둘 다 필수)

| 파일 | 역할 |
|---|---|
| `ux-philosophy.md` | AI가 읽기 위한 구조화 원문 (§3 구성을 그대로 따름) |
| `ux-philosophy.html` 또는 `ux-philosophy.png` | 팀원이 보기 위한 시각 버전 |

HTML을 선택하면 기존 Presentation System 재사용을 권장합니다. PNG를 선택하면 원칙 3~5개를
한 화면에 요약한 카드형 인포그래픽 형태를 권장합니다. 어느 쪽이든 §3의 md 원문과 내용이
같아야 합니다 — 시각 버전에서만 새로운 주장을 추가하지 않습니다.

## 5. 체크리스트

- [ ] 이 문서에 특정 컴포넌트명·색상 hex·px 값이 원칙 서술 안에 직접 등장하지 않는가
- [ ] 디자인 시스템 컴포넌트가 전부 교체돼도 각 원칙 문장이 여전히 성립하는가
- [ ] 예시를 넣었다면 "예시"라고 명확히 라벨링했는가
- [ ] md 원문과 시각본(html/png)의 내용이 일치하는가
