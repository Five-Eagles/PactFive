# 문서 확장 판단

새 문서를 만들지, 기존 문서를 확장할지 판단할 때 쓰는 기준입니다.

## 판단 순서

1. 이 내용이 이미 있는 문서의 주제인가? → 그 문서에 추가한다. 새 문서를 만들지 않는다.
2. 주제는 새롭지만, 기존 문서가 아직 짧고 자연스럽게 이어지는 하위 주제인가? → 기존 문서에
   섹션을 추가한다.
3. 완전히 새로운 개념이거나, 기존 문서에 넣으면 그 문서의 역할이 흐려지는가? → 새 문서를
   만든다.

**새 기능이 생겼다고 새 문서를 만들지 않는다.** 대부분의 새 기능은 이미 있는 문서의 새 항목일
뿐이다 (API 계약 문서에 새 엔드포인트 추가, ERD에 새 엔티티 추가 등). 이번 세션에서 실제로
반복된 패턴이기도 하다 — `integration-workflow.md`, `feature-workflow.md`는 여러 AGENTS.md에
흩어질 뻔한 내용을 하나로 모은 결과다.

## 확장은 항상 "파일 1개 + 인덱스 1줄"의 형태를 갖는다

새 ADR을 추가할 때 기존 ADR 파일을 고치지 않는 것처럼, 새 기능·새 템플릿·새 문서를 추가할 때도
공유 파일을 직접 고치는 형태가 아니라 파일을 하나 추가하고 인덱스(루트 `index.md`, 루트
`AGENTS.md` 등)에 한 줄만 추가하는 형태를 유지한다. 확장할 때마다 여러 사람이 공유하는 파일의
본문을 고쳐야 한다면, 그 확장 방식 자체를 다시 검토한다.
