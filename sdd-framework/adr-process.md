# ADR 작성 여부 판단

`docs/decisions/`에 ADR을 새로 쓸지 판단하는 기준입니다.

## 언제 ADR이 필요한가

아래 중 하나라도 해당하면 ADR을 쓴다. 하나도 해당하지 않으면 ADR 없이 바로 진행한다 (단순 버그
수정, 기존 패턴을 그대로 따르는 신규 기능 등).

1. 여러 폴더·담당자 영역에 걸치는 결정인가 (예: `app/` 접근 권한처럼 전원에게 적용되는 규칙)
2. 나중에 되돌리기 비용이 큰가 (예: 리포 구조, 접근 권한 모델)
3. 여러 대안을 실제로 검토하고 그중 하나를 고른 결정인가
4. 나중에 코드만 보고는 "왜 이렇게 했는지" 재구성할 수 없는가

## ADR은 확정 후 수정하지 않는다

`상태: 확정`이 된 ADR의 "결정"·"영향 재평가"·"위험" 같은 **결정 내용 자체**는 이후에 고치지 않는다.
결정이 바뀌면 새 ADR을 쓰고 기존 ADR의 상태를 "대체됨(ADR-000X로)"로 바꾼다.

단, 오탈자 수정이나 **결정이 실제로 어떻게 실행됐는지에 대한 참고 기록**(예: "이 결정이 v6
스켈레톤에 이렇게 반영됐다")은 예외다 — 결정 내용을 바꾸는 게 아니라 결정이 실행된 사실을
남기는 것이므로, "구현 기록" 섹션으로 명확히 표시해 별도로 추가할 수 있다. 표시 없이 결정
섹션에 섞어 넣지 않는다.
