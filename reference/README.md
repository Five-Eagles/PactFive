# reference/ — 프로젝트 공통 구현 예시 (고정본)

이 폴더는 여러 기능 담당자가 프론트엔드 구현 시 참고하는 **고정된 스냅샷**을 모아둔다.
`features/{기능}/design/`처럼 담당자가 계속 갱신하는 살아있는 원본과 다르다 — 여기 있는
파일은 특정 시점의 버전을 그대로 얼려 둔 것이라, 원본이 나중에 바뀌어도 이 폴더는 저절로
따라가지 않는다.

**왜 원본을 직접 가리키지 않고 고정본을 따로 두는가**: 여러 기능 담당자가 동시에 구현을
진행하는 동안 참고 기준이 계속 바뀌면 "어제 본 화면과 오늘 화면이 다르다"는 혼란이 생긴다.
스프린트 기간 동안은 기준을 고정해 흔들리지 않게 하고, 원본 쪽 갱신은 그 담당자의 작업에는
계속 반영되도록 둔다(아래 "원본과의 관계" 참고).

### 원본과의 관계

- **원본은 훼손하지 않는다.** `features/project-management/design/reference-proposal/`은
  담당자(유동우)가 계속 갱신하는 살아있는 원본이고, 이 폴더의 파일은 그 원본의 한 시점을
  복사한 것뿐이다. 원본을 계속 고쳐도 이 폴더는 영향받지 않는다.
- **다른 기능 담당자는 이 폴더(고정본)를 본다.** `features/project-management/`가 아닌
  다른 기능(applications·contracts-payments·reviews 등)의 화면을 구현할 때 참고하는 대상은
  이 폴더다 — 스프린트 중 원본이 바뀌어도 참고 기준이 흔들리지 않게 하려는 목적이다.
- **project-management 본인은 계속 원본을 본다.** 담당자 본인의 작업 기준은 여전히
  `reference-proposal/`의 살아있는 원본이다. 이 폴더는 담당자 본인의 작업 기준을 대체하지
  않는다.
- **다시 얼리려면**: 팀장이 원본에서 `bundle.html`을 다시 빌드해 이 폴더의 파일을 교체하고,
  이 표의 "고정 시점"·"고정 시점 커밋"을 갱신한다. 자동으로 갱신되지 않는다 — 갱신이 필요하다고
  판단되면(예: 원본에 구조적으로 중요한 변경이 생겼을 때) 팀 논의를 거쳐 결정한다.

### 범위 — 화면 10장 중 확정 참고 대상은 7장

번들에는 화면 10장이 들어 있지만, 이 중 3장(`experts.html`·`expert.html`·`guide.html`)은
**확정된 참고 대상이 아니다.**

| 화면 | ERD·PRD 근거 | 담당 | 참고 대상 여부 |
|---|---|---|---|
| 대표페이지(main) · 프로젝트 찾기(browse) · 프로젝트 상세(detail) · 프로젝트 등록(register) · 마이페이지(mypage) · 프로젝트 수정(edit) · 다시 모집하기(reopen) | 있음 (PRD §7.1·SCR-B01~B10) | 유동우 (CR-0011) | **확정 — 구조·원칙 참고용으로 쓴다** |
| 전문가 찾기(experts) · 전문가 프로필(expert) · 이용 방법(guide) | **없음** — PRD 화면 목록에 없고, 표시 필드(접속 상태·인증 배지 등)도 `docs/domain/erd.md`에 없는 컬럼이 섞여 있다(`reference-proposal/README.md` 참고) | 정해지지 않음 | **향후 검토 대상 — 지금은 구현 예시로 쓰지 않는다** |

이 3장은 유동우가 "형식만 제안"이라고 스스로 표시해 둔 것이지, 팀이 확정한 기능 범위가
아니다. ERD·PRD에 근거가 생기고 담당자가 정해진 뒤에 다시 검토한다 — 지금 이 화면들을 다른
기능의 구현 근거로 삼지 않는다.
